Autoware 0.47.1 Multi Object Tracker 環境構築手順
====================================================

目的
----
Autoware Universe 0.47.1 の autoware_multi_object_tracker を、
FastBEVとは別のROS 2 workspaceで単体ビルド・起動できる環境を構築する。

構成
----
~/autoware_tracking_ws/
├── src/
│   ├── autoware_universe/
│   ├── autoware_cmake/
│   ├── autoware_msgs/
│   ├── autoware_internal_msgs/
│   ├── autoware_utils/
│   ├── autoware_core/
│   ├── muSSP/
│   └── glog/
├── build/
├── install/
└── log/

10. glog問題への対応
--------------------
autoware_multi_object_tracker 0.47.1 は
google::IsGoogleLoggingInitialized() を使用する。

Ubuntu 22.04標準の libgoogle-glog-dev ではAPIが合わず、
Autoware 0.47.1当時のTIER IV fork版glogを使用する。

cd ~/autoware_tracking_ws/src

git clone https://github.com/tier4/glog.git
cd glog
git checkout ea36766fdc2ac8e8c8e3ac988ae69acd6d09bb30
cd ..

確認:
cd ~/autoware_tracking_ws
colcon list | grep glog

期待例:
glog    src/glog    (ros.ament_cmake)

12. glogのCMake参照先問題
-------------------------
最初のTrackerビルドではCMakeCacheがUbuntu標準glogを参照していた。

確認:
grep "^glog_DIR" build/autoware_multi_object_tracker/CMakeCache.txt

誤った参照例:
glog_DIR:PATH=/usr/lib/x86_64-linux-gnu/cmake/glog

TIER IV版glogには以下が存在する:
grep -n "IsGoogleLoggingInitialized" install/glog/include/glog/logging.h

期待:
GLOG_EXPORT bool IsGoogleLoggingInitialized();

Trackerの古いCMakeCacheを削除:
cd ~/autoware_tracking_ws
rm -rf build/autoware_multi_object_tracker
rm -rf install/autoware_multi_object_tracker

TIER IV版glogの正しいCMake package:
~/autoware_tracking_ws/install/glog/lib/cmake/glog

13. 最終ビルドコマンド
---------------------
source /opt/ros/humble/setup.bash

CMAKE_BUILD_PARALLEL_LEVEL=1 MAKEFLAGS="-j1" colcon build --executor sequential --packages-up-to autoware_multi_object_tracker --cmake-args -Dglog_DIR=/home/kenta/autoware_tracking_ws/install/glog/lib/cmake/glog

ポイント:
- --executor sequential:
  パッケージを順番にビルドする
- CMAKE_BUILD_PARALLEL_LEVEL=1:
  CMakeの並列数を1に制限
- MAKEFLAGS="-j1":
  make側も1並列に制限
- --packages-up-to:
  Trackerと、その依存パッケージまでを依存順にビルド
- -Dglog_DIR=...:
  Ubuntu標準glogではなくTIER IV版glogを明示的に使用

16. map -> base_link のstatic TF
-------------------------------
単体試験ではmapとbase_linkを一致させる。

確認:
ros2 run tf2_ros tf2_echo map base_link

18. 今回理解したポイント
------------------------
1. Autoware Universe全体を入れず、
   Trackerに必要なパッケージだけをsparse checkout / cloneした。

2. Trackerは単体では動かず、
   Autoware内部のmsgs、utils、core、muSSPなどに依存する。

3. rosdepは、workspace内に存在しないUbuntu/ROS側の外部依存を入れる。

4. colcon build --packages-up-to は、
   Trackerと、その依存パッケージを依存順にビルドする。

5. CMakeは一度見つけた依存先をCMakeCache.txtに保存する。
   依存ライブラリを変えた場合はbuildディレクトリの再生成が必要になることがある。

6. Autoware 0.47.1ではUbuntu標準glogではなく、
   TIER IV fork版glogを使う必要があった。

7. ROS 2で実際に利用する完成物は主にinstall/以下に生成され、
   source install/setup.bash でROS 2から利用可能になる。

8. 今回、DetectedObjects -> Multi Object Tracker -> TrackedObjects
   の単体疎通確認まで完了した。
